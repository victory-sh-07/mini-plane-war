# 飞机大战(mini-plane-war)

## 项目简介
大一暑假自学python完成极简版飞机大战小游戏

## 技术栈
Python 3.12 / Pygame / Git

## 如何运行
1.安装依赖：pip install pygame
2.运行：python main.py

## 操作说明
- <- -> 操控飞机左右移动
- 空格 发射子弹
- R 重开

## 功能清单
- 玩家移动与射击
- 敌机随机生成与下落
- 碰撞检测与实时计分
- 游戏结束与重开
- 最高分本地存档

## 学习记录

### Day 1：环境搭建与第一个窗口
- 选题时对比过几个方向，最后选了 Pygame，理由是：纯 Python、不用学前端、演示效果直观。
- 不想把项目放 C 盘，学会了用绝对路径把项目安到 D 盘。
- 被 C 语言惯坏了，一开始总找 main 函数在哪，后来才知道 Python 从上往下执行，文件本身就是 main。
- 第一个窗口一闪就没了，想了很久才明白：没有死循环“吊着”，程序执行完就结束。这就是游戏主循环。
- 学会 git init / add / commit，理解了“工作区 → 暂存区 → 仓库”三个区。
- 第一次 push 报 Connection was reset，慌了一下；后来连手机热点、完成浏览器授权才成功。

### Day 2：飞机动起来
- 用 Rect 表示飞机，draw.rect 画绿色矩形当替身——先验证逻辑，再谈美术。
- 用 key.get_pressed() 读按键。一开始不懂 clock.tick(60) 干嘛，删掉试了一次，飞机快得像瞬移，从此记住帧率。

### Day 3：子弹飞起来
- 用列表管理一群子弹，总结出固定套路：生成 append / 每帧更新 / 出界清理 / 逐颗绘制。
- 搞懂了 KEYDOWN 和 get_pressed 的区别：发射是“一次性”，移动是“持续”，不能混用。
- 遍历时删除要遍历副本 bullets[:]，否则会漏元素，这个坑自己试出来了。

### Day 4：敌机从天而降
- 用 random.randint 让敌机位置随机，用 frame_count % 60 当定时器，每秒生成一架。
- 发现敌机代码和子弹代码结构几乎一样——列表套路可以复用，这大概就是“模式”。

### Day 5：碰撞与计分
- 用 colliderect 判断矩形重叠，双层循环让子弹和敌机两两配对；break 保证一颗子弹只换一架敌机。
- 用 font.render + blit 显示分数。踩坑：默认字体不认识中文，屏幕全是方块，只好写英文 Score。
- commit 时报 not a git repository，以为仓库坏了，结果是终端站错了目录——git 只认你“当前站在哪”。
- 把 bullet 拼成 buttle，虽然不报错但很难读，统一改正了。

### Day 6：游戏结束与重开（踩坑最深的一天）
- 用 game_over 开关管理“进行中 / 已结束”，玩法逻辑关进 if not game_over 闸门。
- 坑一：把事件循环也关进了闸门，结束后 R 键、关闭按钮全失灵。用 print 打印按键值，发现结束后毫无输出——程序的“耳朵”被堵死了，把事件循环移回闸门外才解决。
- 坑二：修好后 R 还是没反应。print 显示空格、PrintScreen 都通，唯独字母 R 没输出，最后发现是中文输入法吞了字母键。加了回车做备用重开键解决。
- 这两个 bug 教会我：调试要让程序自己说话（print），不要盯着代码空想。

### Day 7：游戏有了“记忆”
- 用 with open 把最高分存进 high_score.txt；第一次运行没有文件，用 try/except 接住 FileNotFoundError。
- 彻底理解了一句话：只发生一次的东西放循环外，每帧发生或事件触发的放循环内。

### 写在最后
从“不会写 Python”到一个完整的小游戏，我学到的不只是 Pygame，
更是“遇到 bug → 提出假设 → 用 print 验证 → 修复”的底气。
